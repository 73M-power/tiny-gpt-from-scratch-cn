# GitHub 开源前检查清单

这份清单用于课程完成后把项目发布到 GitHub。发布属于外部写操作，应在最终检查完成并由项目所有者明确确认后执行。

## 内容完整性

- [ ] 12 课正文全部完成并经过实际运行验证。
- [ ] README 清楚说明项目目标、受众、限制和运行方式。
- [ ] 每个命令从全新虚拟环境中都能执行。
- [ ] 代码注释与教程中的名称、shape 和默认参数一致。
- [ ] 示例输出明确标注为教学模型结果，不夸大模型能力。

## 代码质量

- [ ] 单元测试全部通过。
- [ ] 训练、保存、加载、生成链路全部通过。
- [ ] 固定随机种子时结果可复现到合理程度。
- [ ] 无本机绝对路径写入源码或文档。
- [ ] 无密码、token、密钥、个人数据或机器标识。
- [ ] `.venv/`、缓存、系统文件和临时 checkpoint 已由 `.gitignore` 排除。

## 数据与模型

- [ ] 训练语料来源与使用权清晰。
- [ ] 自建语料明确标注；第三方语料记录来源与许可。
- [ ] 决定是否提交教学 checkpoint；若提交，说明大小、配置与训练数据。
- [ ] 检查 GitHub 单文件大小限制和仓库总体积。

## 开源元数据

- [x] 由项目所有者选择 MIT License，并添加根目录 `LICENSE`。
- [ ] 添加 `CONTRIBUTING.md`，说明问题反馈和贡献流程。
- [ ] 添加行为准则或明确项目交流边界（如果需要外部贡献）。
- [ ] 添加版本信息或 changelog 方案。
- [ ] README 中提供课程目录、环境要求、快速开始和常见问题。

## 发布流程

- [ ] 确认 GitHub 仓库名称与公开/私有设置。
- [ ] 本地初始化或确认 Git 仓库边界，避免误提交上层目录文件。
- [ ] 审核 `git status` 与即将提交的每个文件。
- [ ] 创建首个清晰提交。
- [ ] 经项目所有者授权后创建远端并 push。
- [ ] 在 GitHub 页面再次检查 Markdown 链接、代码块和目录导航。
